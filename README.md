# 2026_KOSSCCTHON

## TripClip

> 숏폼 콘텐츠에서 발견한 장소와 활동을 저장하고, AI가 사용자별 취향을 분석하여 여러 사용자의 취향이 반영된 공동 일정 및 여행 코스를 생성하는 서비스

---

## 1. Problem

친구들과 여행이나 약속을 계획할 때 Instagram Reels, YouTube Shorts, TikTok 등에서 가고 싶은 장소를 발견해 서로 공유합니다.

하지만 실제 일정을 계획할 때는 다음과 같은 문제가 발생합니다.

- 가고 싶은 장소가 여러 SNS와 채팅방에 흩어져 있습니다.
- 이전에 공유한 숏폼 콘텐츠를 다시 찾기 어렵습니다.
- 구성원마다 원하는 장소와 취향이 다릅니다.
- 여러 사람의 의견을 비교하고 조율하는 과정이 필요합니다.
- 결국 특정 한 사람이 장소를 정리하고 일정을 계획하는 경우가 많습니다.

TripClip은 이러한 문제를 해결하기 위해 숏폼 콘텐츠를 단순히 저장하는 것에서 끝나지 않고, 각 사용자의 콘텐츠를 취향 데이터로 변환하여 공동 일정 생성에 활용합니다.

---

## 2. Solution

TripClip은 사용자가 공유하거나 저장한 숏폼 콘텐츠에서 AI를 이용해 장소와 활동 정보를 구조화합니다.

저장된 콘텐츠가 누적되면 사용자별 취향 DB를 생성하고, 여행이나 약속을 함께하는 구성원들의 취향을 분석합니다.

이후 다음 정보를 종합하여 공동 일정을 생성합니다.

- 각 사용자가 저장한 장소
- 사용자별 취향
- 구성원들의 공통 관심사
- 여행 지역
- 날짜 및 시간
- 이동 동선
- 추가 요청사항

단순히 장소를 모아주는 것이 아니라, 특정 한 사람의 취향에 치우치지 않도록 구성원들의 취향을 조율하는 것을 목표로 합니다.

---

## 3. Core Concept

기존의 숏폼 기반 여행 서비스가 콘텐츠에서 장소를 추출하고 일정을 정리하는 데 집중한다면, TripClip은 숏폼 콘텐츠를 사용자의 취향을 나타내는 데이터로 활용합니다.

```text
Short-form Content
        ↓
AI Content Analysis
        ↓
Personal Preference DB
        ↓
Group Preference Analysis
        ↓
Preference Balancing
        ↓
AI Itinerary Generation
        ↓
Shared Schedule
```

핵심은 다음과 같습니다.

> 각자가 공유한 숏폼에서 취향을 분석하고, 여러 사람의 취향을 조율하여 모두가 만족할 수 있는 공동 경험을 만든다.

---

## 4. Key Features

### 4.1 숏폼 콘텐츠 저장

사용자는 SNS에서 발견한 콘텐츠를 TripClip에 저장할 수 있습니다.

지원 대상

- Instagram Reels
- YouTube Shorts
- TikTok

해커톤 MVP에서는 숏폼 URL과 플랫폼에서 접근 가능한 공개 정보 및 사용자 입력을 활용합니다.

---

### 4.2 AI 콘텐츠 분석

숏폼 콘텐츠의 제목, 설명, 해시태그 등의 정보를 AI가 분석하여 일정 생성에 사용할 수 있는 데이터로 구조화합니다.

추출 대상 예시

- 장소명
- 지역
- 카테고리
- 활동
- 키워드
- 추천 시간대

예시

```json
{
  "place_name": "성수 전시회",
  "area": "성수",
  "category": "exhibition",
  "keywords": [
    "전시",
    "데이트",
    "사진"
  ],
  "recommended_time": "afternoon"
}
```

AI가 정확하게 판단하기 어려운 정보는 사용자가 확인하거나 수정할 수 있도록 구성합니다.

---

### 4.3 Shared Trip Basket

그룹 구성원들이 저장한 장소를 하나의 공동 공간에서 확인할 수 있습니다.

예시

```text
원영
- 성수 카페
- 일식 맛집
- 서울숲

민수
- 팝업스토어
- 빈티지숍

지수
- 전시회
- 디저트 카페
```

이를 통해 SNS나 채팅방에 흩어져 있던 여행 및 약속 정보를 하나의 공간에서 관리합니다.

---

### 4.4 Personal Preference DB

사용자가 저장한 콘텐츠를 기반으로 개인별 취향 정보를 누적합니다.

예시

```text
원영

Cafe        0.82
Food        0.71
Exhibition  0.64
Activity    0.43
Shopping    0.21
```

사용자가 특정 카테고리의 콘텐츠를 반복적으로 저장할수록 해당 취향의 가중치가 높아집니다.

취향 DB는 사용자가 직접 작성하는 프로필이 아니라 실제 저장 행동을 기반으로 생성하는 것을 목표로 합니다.

---

### 4.5 Group Preference Analysis

여행방에 참여한 사용자들의 취향 DB를 비교하여 그룹의 공통 관심사와 개인별 특성을 분석합니다.

예시

```text
원영
Cafe / Food / Exhibition

민수
Shopping / Popup / Activity

지수
Exhibition / Cafe / Photo
```

AI는 다음과 같은 정보를 분석합니다.

- 여러 구성원이 공통적으로 좋아하는 활동
- 특정 사용자만 선호하는 활동
- 구성원 간 취향 차이
- 일정에 아직 충분히 반영되지 않은 사용자의 취향

---

### 4.6 AI Itinerary Planner

그룹의 저장 콘텐츠와 취향 데이터를 기반으로 AI가 공동 일정을 생성합니다.

입력 정보 예시

```text
지역: 성수

날짜: 토요일

시간:
13:00 ~ 20:00

참여자:
원영 / 민수 / 지수

조건:
저녁 식사 포함
1인 예산 50,000원 이하
```

결과 예시

```text
13:00
성수 팝업스토어

→ 민수의 팝업 및 쇼핑 취향 반영

15:00
전시회

→ 지수의 전시 취향 반영
→ 원영의 문화 콘텐츠 취향 일부 반영

17:00
디저트 카페

→ 원영과 지수의 카페 취향 반영

19:00
일식집

→ 원영의 음식 취향 반영
→ 그룹의 저녁 식사 조건 충족
```

---

### 4.7 Preference Balance

TripClip의 핵심 차별점 중 하나입니다.

AI가 일정을 생성할 때 단순히 인기 장소를 추천하는 것이 아니라, 각 구성원의 취향이 일정에 얼마나 반영됐는지 확인합니다.

예시

```text
취향 반영도

원영 83%
민수 78%
지수 85%
```

반영도는 AI가 임의로 생성하는 값이 아니라, 사용자의 취향 카테고리와 실제 일정에 포함된 카테고리를 기반으로 계산하는 것을 목표로 합니다.

이를 통해 특정 한 사람의 취향에 편향된 일정 생성을 줄입니다.

## 6. AI Pipeline

TripClip에서는 AI 기능을 크게 두 단계로 나눕니다.

### AI 1. Content & Preference Analyzer

역할

```text
숏폼 정보
    ↓
콘텐츠 분석
    ↓
장소 / 카테고리 / 키워드 추출
    ↓
사용자 취향 DB 업데이트
```

입력

```json
{
  "url": "short-form-url",
  "title": "성수에서 꼭 가봐야 할 카페",
  "description": "데이트할 때 추천하는 디저트 카페",
  "hashtags": [
    "성수",
    "카페",
    "데이트"
  ]
}
```

출력

```json
{
  "place_name": "성수 카페",
  "area": "성수",
  "category": "cafe",
  "keywords": [
    "dessert",
    "date",
    "cafe"
  ],
  "recommended_time": "afternoon"
}
```

---

### AI 2. Group Itinerary Planner

역할

```text
개인 취향 DB
+
그룹 저장 장소
+
날짜 / 시간 / 지역
+
사용자 조건
        ↓
그룹 취향 분석
        ↓
취향 조율
        ↓
공동 일정 생성
```

출력 예시

```json
{
  "summary": "세 명의 카페, 전시, 쇼핑 취향을 균형 있게 반영한 성수 코스입니다.",
  "schedule": [
    {
      "time": "13:00",
      "place": "성수 팝업스토어",
      "category": "shopping",
      "related_users": [
        "민수"
      ],
      "reason": "민수의 팝업 및 쇼핑 취향을 반영했습니다."
    },
    {
      "time": "15:00",
      "place": "성수 전시회",
      "category": "exhibition",
      "related_users": [
        "원영",
        "지수"
      ],
      "reason": "지수의 전시 취향과 원영의 문화 콘텐츠 취향을 반영했습니다."
    }
  ]
}
```

## 13. Difference

TripClip은 숏폼 콘텐츠에서 장소를 추출하여 여행 일정을 만드는 것만을 목표로 하지 않습니다.

숏폼 콘텐츠를 각 사용자의 취향을 나타내는 데이터로 해석하고, 여러 사용자의 취향을 분석 및 조율하여 공동 일정에 반영합니다.

```text
기존 접근

숏폼
→ 장소 추출
→ 장소 저장
→ 여행 일정


TripClip

숏폼
→ 장소 및 취향 추출
→ 개인 취향 DB
→ 그룹 취향 분석
→ 취향 조율
→ 공동 일정
```

핵심 차별점은 다음과 같습니다.

> 장소를 정리하는 것이 아니라 사람들의 취향을 조율한다.

## 14. Goal

TripClip의 최종 목표는 사용자가 직접 여행 취향을 일일이 입력하지 않아도, 평소 저장하고 공유하는 콘텐츠를 통해 자연스럽게 취향을 파악하는 것입니다.

그리고 여러 사람이 함께 계획을 세울 때 각자의 취향과 관심사를 AI가 분석하여 특정 한 사람에게 계획 부담이 집중되지 않도록 지원합니다.
